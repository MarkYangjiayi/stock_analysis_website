# Quantify 前端设计升级计划

日期：2026-09-10

状态：规划稿，待实施

适用项目：`stock_analysis_website/frontend`
首轮范围：全站视觉规范、公共基础组件、个股分析页样板

## 1. 目标与设计方向

将 Quantify 升级为克制、精致、信息分层清晰的专业投研工作台。通过布局、字体、色彩、图表和交互的一致性，提升现代感，同时让重要信息更容易找到、理解和比较。

### 1.1 核心目标

1. **快速理解**：进入个股页后，首先识别股票、价格口径与日期、估值情景和关键风险。
2. **渐进阅读**：用户可以从摘要进入财务证据、估值假设、同行比较和事件研报，始终知道自己所在的位置。
3. **高效比较**：表格、情景和财务数据采用一致的单位、对齐和格式，减少来回查找。
4. **可信表达**：保留数据来源、时点、缺失原因和估值假设，清楚区分事实、模型结果和 AI 解读。
5. **跨设备可用**：桌面端支持高密度研究，移动端支持快速查看与必要操作。
6. **可持续维护**：将设计规则落实为可复用组件与语义变量，减少页面之间的样式偏差。

### 1.2 风格定位

- 保留 Quantify 名称、翡翠绿品牌识别与浅深色主题。
- 浅色主题采用浅灰画布、白色内容面板、深色正文。
- 深色主题采用石墨色画布、分层灰色面板、清晰的正文与图表对比。
- 通过整齐的对齐线、精确的数字排版和克制的留白形成设计感。
- 图表和研究数据为视觉主体；装饰性渐变、插画和大面积动画不进入首轮范围。
- 界面文案沿用当前英文；本计划使用中文。完整国际化另行规划。

### 1.3 首轮不包含的工作

- 后端 API、数据库结构、估值算法、因子定义或数据同步机制改造。
- 交易执行、实时行情接入、新的 AI 能力或综合股票评分。
- 迁移前端框架、替换全部图表库或全面引入大型组件库。
- 新增全站设置中心、用户系统或云端偏好存储。
- 自动发布部署；发布作为完成验证后的独立交付步骤处理。

## 3. 信息架构与导航

### 3.1 全局导航

保留五个主要入口及现有路由：

| 入口 | 路由 | 主要任务 |
| --- | --- | --- |
| Analysis | `/` | 研究一家公司 |
| Screener | `/screener` | 筛选与比较候选公司 |
| Anomalies | `/anomalies` | 查看市场异动 |
| Market | `/market` | 理解市场与板块状态 |
| Factor Lab | `/research` | 因子研究与回测 |

`/rrg` 保持现有访问能力，并作为 Market 下的相关视图处理。

全局搜索继续支持股票代码与现有 ticker URL。输入示例和错误反馈清楚说明支持格式；搜索联想、公司名检索只有在现有接口支持时才纳入，不能仅靠新文案承诺能力。

### 3.2 个股研究结构

采用“持续可见的股票上下文 + 概览摘要 + 明确的研究分区”。

建议最终分区：

| 分区 | 内容 | 现有模块去向 |
| --- | --- | --- |
| Overview | 行情摘要、估值情景摘要、关键风险、重要事件、研究入口 | StockSnapshotPanel 与驾驶舱概览内容 |
| Valuation | Bear/Base/Bull、假设编辑、敏感性、隐含增长、同行比较 | 驾驶舱 Valuation、Peer Benchmarks |
| Financials | 财务趋势、财务流向、盈利质量与数据质量细节 | FinancialTrendChart、FinancialFlowPanel、EarningsQualityPanel |
| Technical | 价格与成交量、现有技术指标、因子快照独立区域 | StockChart、PointInTimeFactorPanel；明确因子并非全部属于技术指标 |
| Events & Brief | 事件预期、新闻、AI 简报和引用证据 | EventsExpectationsPanel、NewsFeed、AIReport |

技术分区名称在样板验证时评估：若混合因子易产生误解，改为 `Price & Factors`，以准确描述实际内容。首轮不为统一版式强行更改指标含义。

### 3.3 导航整合策略

1. 先拆出驾驶舱各内容区的展示组件，保留原有计算、保存与权限逻辑。
2. 使用一层个股主分区导航；同行比较在估值区作为子章节，风险详情从常驻风险摘要进入。
3. 迁移期间可以先使用页面锚点，但不得让两套主标签长期并存。
4. 保留 ticker 查询参数；分区使用稳定 URL 参数或锚点，最终实现前统一一种方案。
5. 浏览器前进后退可恢复股票和分区；筛选与周期状态遵循已有 URL 行为。
6. 从任何证据入口跳转时，先激活目标分区，再选择指标，最后滚动和定位焦点。
7. 切换分区保留未保存假设；不得因组件卸载而丢失输入或重复触发生成任务。

## 4. 个股分析页详细设计

### 4.1 桌面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ Quantify   Analysis  Screener  Anomalies  Market  Factor Lab   │
│                                     股票搜索       主题切换   │
├─────────────┬────────────────────────────────────────────────┤
│ 自选列表    │ 股票名称 / 代码 / 交易所       价格 / 涨跌 / 日期│
│ 当前选中项  │ 概览摘要：估值情景、关键风险、数据状态          │
│ 解锁与编辑  ├────────────────────────────────────────────────┤
│             │ Overview | Valuation | Financials | …          │
│             ├────────────────────────────────────────────────┤
│             │ 当前分区内容：主要图表或分析                    │
│             │ 详细证据、参数、来源与补充信息                  │
└─────────────┴────────────────────────────────────────────────┘
```

该图是结构示意，具体行数与折叠方式以高保真样板验证为准。桌面首屏优先呈现上下文、摘要及主要分析入口。

### 4.2 股票摘要

- 公司名称与代码形成主次关系；长名称允许换行，不能挤出价格。
- 价格旁保留币种、价格日期和复权口径；现有 adjusted close 不改称实时价格。
- 涨跌显示正负号、百分比与方向标识，零变化有独立中性状态。
- 公司描述默认简短展示，提供 `Show more / Show less` 明确按钮。
- 加入自选、已加入、锁定状态位置稳定，触发后提供局部反馈。
- 向下滚动时可收缩为简洁股票栏；移动端避免多层吸顶占满屏幕。

### 4.3 概览摘要

首批候选信息为当前价格、Bear/Base/Bull 估值、已有安全边际或相关输出、关键风险数量与数据状态。最终字段必须对应已有 API，不新增前端推导的综合评分。

- 估值优先使用三情景并排比较或简洁区间图，标出当前价格位置。
- 三个情景有固定名称和明确假设入口，不让 Base 看起来像确定的预测价格。
- 关键风险保留标题和可见原因；完整规则与证据进入详情。
- 数据状态分别标明价格、财报、因子等来源日期，不合并成误导性的单一“更新于”。
- 缺失数据用 `—` 并说明原因；不把缺失显示为 0、正常或低风险。
- AI 简报位于深入解读区，摘要主要由已有确定性结果组成。

### 4.4 估值与同行比较

- 结果区优先，参数区紧随；桌面可双栏，窄屏按结果、参数顺序排列。
- 参数区区分服务器已保存值与当前工作假设，保留保存、重置和未保存提示。
- 保留估值不可用、证据不同步和未授权状态的现有约束。
- 敏感性矩阵采用清楚的轴标题、单位、选中值和图例；颜色之外保留数字。
- 同行比较固定指标列，数值右对齐；原始分位、方向调整后分位和覆盖率清晰区分。
- 大量指标按主题组织，默认展示常用集合，仍可访问完整指标。

### 4.5 财务、图表与证据

- 年度、季度和 TTM 切换位置一致，但只展示对应模块实际支持的选项。
- 保留 FinancialFlow 对 TTM 的现有限制，不用上一周期数据冒充当前选择。
- Reported 保持默认；只有满足现有验证条件时并列展示 normalized 或 adjusted 数据。
- 盈利质量分析按单期明确触发，切换标签、展开组件和主题切换不触发 AI/SEC 调用。
- 图表显示时间范围、币种、金额单位、复权/对数口径和数据来源。
- 证据引用可点击定位到具体指标或详情，返回后保留原来的阅读状态。
- 新闻保留时间与来源；AI 引用与一般新闻链接有明确区分。

## 5. 视觉设计系统

### 5.1 色彩与主题

优先扩展 `globals.css` 现有变量，避免同义变量重复存在。

| 语义 | 建议职责 |
| --- | --- |
| app-bg | 页面画布 |
| surface / surface-muted / surface-raised | 内容、嵌入区与浮层 |
| border / border-strong | 默认分隔与交互强调 |
| text / text-muted | 正文与辅助信息，均需检查对比度 |
| brand / brand-strong / brand-soft | 主操作、选中和品牌强调 |
| positive / negative / neutral | 涨跌或明确的数值方向 |
| warning / danger / info | 警告、错误与说明 |
| chart-series-* | 多序列图表配色，独立于涨跌含义 |

- 品牌绿和上涨绿即使色相接近，也保留独立语义定义。
- 沿用现有涨跌配色习惯；可配置红涨绿跌留待后续需求确认。
- 每个图表系列在不同页面与浅深主题中保持稳定身份。
- 图表颜色通过统一主题适配层提供，避免仅 HTML 随主题变化。
- 普通文本对比度目标至少 4.5:1，大文本至少 3:1；深浅主题分别验证。

参考：[W3C WCAG 2.2 — Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。这些是验收目标，并非当前项目已达到的结论。

### 5.2 排版

| 用途 | 建议字号 | 字重与说明 |
| --- | --- | --- |
| 页面标题 | 24–30px | 600–700，避免常规使用 900 |
| 关键价格 / 摘要数字 | 28–36px | 600–700，等宽数字 |
| 模块标题 | 16–18px | 600 |
| 正文与主要表格 | 14–16px | 400–500 |
| 辅助信息 / 图例 | 12–13px | 400–500，不能通过过浅颜色弱化到难读 |

- 默认使用完整系统字体栈和中文回退；是否增加品牌字体以样板效果与加载成本决定。
- 数值采用 `font-variant-numeric: tabular-nums`，代码和证据 ID 可使用等宽字体。
- 同列金额统一精度；百分比、倍数、日期、负号、缺失值集中格式化。
- 缩写金额展示单位，交互详情可读取完整数值；手机上可通过点击读取。
- 金额、价格与估值保留币种；不同币种不直接形成未经换算的视觉比较。

### 5.3 间距、面板与控件

- 基础间距：4、8、12、16、24、32px。
- 面板圆角建议 12–16px，输入框与按钮 8–10px，状态标签使用小圆角或胶囊形。
- 普通面板以边框和背景区分，明显阴影主要用于弹层。
- 同一分析区内减少“卡片套卡片”，采用标题、分隔线和局部背景。
- 桌面控件高度约 36–40px；移动主要操作触控区目标至少 44px。
- 同组控件统一高度、文字基线与图标尺寸。
- 动效约 120–180ms，尊重 `prefers-reduced-motion`，不对行情数字持续闪烁。

## 7. 其他页面推广方案

### 7.1 Screener

- 页面顶部显示结果数量、已发布快照日期与主要动作。
- 常用筛选优先展示，高级条件折叠；保留当前字段范围、覆盖率和缺失值处理规则。
- 已应用条件以可删除标签展示，重置入口稳定；编辑值与已应用值若不同应清楚标识。
- 沿用已有请求触发模式；需要即时筛选时再使用防抖，避免样式改造改变请求节奏。
- 固定表头与股票识别列，数字右对齐，排序状态可见。
- 列选择以常用列开场；更多指标可展开，不强制所有指标同时占据屏幕。
- 空结果区保留当前条件并提供清除条件动作。
- 移动端保留少量关键列，其他列在表格自身横向滚动区域中访问。

### 7.2 Market

- 顶部摘要只使用已有返回字段，例如样本数量、价格覆盖率和 MA200 宽度。
- Universe、Period、Mode 控件分组一致，已禁用市场继续显示不可用原因。
- 保留板块趋势与市场宽度的联动时间轴。
- 图例支持聚焦少量系列，完整系列始终可恢复。
- 图表密度高时优先调整默认可见系列和高度，不缩小文字。
- Market 与 RRG 使用一致的页头、主题和入口关系。

### 7.3 Anomalies

- 扫描控制区与最新扫描结果分离。
- 最新扫描时间、运行中、完成、失败及空结果状态明确。
- 异动条目展示股票、类型、触发值/规则、时间和分析入口。
- 强度只采用现有字段；没有可靠强度字段时按类型和时间组织，不创造评分。
- 手机默认保持可读条目，桌面可根据实际列数选择列表或表格。

### 7.4 Factor Lab

- 清晰区分 Research 与 Backtest 模式。
- 参数按研究范围、信号、组合与成本分组，低频高级参数折叠。
- 结果优先呈现已有收益、回撤等指标及曲线，保留数据覆盖和研究区间。
- 运行中防止重复提交，错误靠近对应操作区。
- 保持密钥、未授权和回测条件校验行为。
- 若接口没有历史结果查询能力，本轮不新增“历史运行列表”占位功能。

## 8. 响应式、可访问性与状态规范

### 8.1 视口策略

| 宽度 | 布局策略 |
| --- | --- |
| ≥1440px | 完整导航、可见自选栏、研究内容可双栏 |
| 1024–1439px | 根据有效内容宽度减少双栏，自选栏可收起 |
| 768–1023px | 紧凑导航与单栏研究，避免侧栏挤压图表 |
| <768px | 单栏、紧凑股票摘要、自选抽屉或现有紧凑入口 |

验收至少覆盖 1440×900、1280×800、768×1024、390×844 和 360px 宽度。断点属于初始设计值，以实际内容溢出情况调整。

- 主页面不产生意外横向滚动；长表格可以在局部滚动。
- 200% 缩放后仍能访问主要操作和数据。
- 移动键盘打开时搜索与弹窗按钮可达。
- 吸顶栏、焦点定位和锚点使用真实滚动容器计算偏移。
- 自选侧栏切换与分区切换后，图表正确 resize；隐藏容器恢复时不出现零宽图表。

### 8.2 可访问性

- 保留跳过导航链接与清楚的主内容区域。
- 真正的标签页使用匹配的键盘交互和 ARIA；锚点导航使用链接语义。
- Tooltip 可由键盘焦点触发；重要说明也能通过点击访问。
- 弹窗管理初始焦点、Escape、焦点限制及关闭后的焦点返回。
- 操作按钮具有可理解名称，图标按钮不依赖图标猜测用途。
- 错误与状态变化使用合适的通知区域，避免每个行情变化都打断屏幕阅读器。
- 图表提供文字摘要或关键数据访问方式，Canvas 不作为唯一信息通道。

### 8.3 状态矩阵

| 状态 | 展示要求 | 操作要求 |
| --- | --- | --- |
| 首次加载 | 接近最终布局的骨架和简短说明 | 不展示假数字 |
| 局部刷新 | 保留同一股票的旧值并明确刷新中 | 防止过期响应覆盖新状态 |
| 切换股票 | 清晰显示正在加载的新股票上下文 | 不把旧股票数据当作新股票显示 |
| 无数据 | 说明当前缺失内容与原因 | 有适当的返回或调整入口 |
| 请求失败 | 局部错误信息 | 可重试且不清空其他成功模块 |
| 数据过期 | 日期和原因可见 | 仅在已有时效规则支持时判定 stale |
| 未解锁 | 明确只读与需解锁操作 | 保留现有解锁流程 |
| 未保存假设 | 明确草稿状态 | 保存、重置，遵守现有 AI 证据同步限制 |
| 分析运行中 | 对应期间的进度状态 | 防重复提交，切换视图不重复发起 |

## 10. 验证计划与验收标准

### 10.1 必须保留的业务语义

1. 价格的日期、币种、复权及尺度标识正确。
2. Bear/Base/Bull、敏感性与市场隐含增长含义不变。
3. 原始分位和方向调整后的同行分位不混用。
4. Reported 与 normalized/adjusted 数据边界不变。
5. AI 仍按需触发，证据验证与不同步禁用条件不变。
6. Point-in-time 日期、版本、覆盖率和缺失原因不丢失。
7. 不增加前端模拟行情、模拟评分或以零代替缺失值的逻辑。

### 10.2 核心流程回归

- 搜索代码 → 个股页 → 加入自选 → 切换股票 → 浏览器返回。
- 调整估值假设 → 切换分区 → 返回仍保留草稿 → 保存/重置。
- 点击财务证据 → 正确分区、周期、指标与定位。
- 切换年度/季度/TTM → 各模块按真实能力显示数据或明确限制。
- 单期盈利质量分析 → 运行状态 → 完成或失败 → 不重复提交。
- AI 生成 → 引用跳转；未保存假设与未授权分支保持正确。
- Screener 修改条件、排序、选列、空结果和进入个股。
- Market 切换时间范围与图例 → 联动与数据口径一致。
- Anomalies 扫描中、无结果、失败和重试。
- Factor Lab 参数校验、运行和结果展示。

### 10.3 自动化检查

在 `frontend` 目录使用项目现有命令：

```bash
npm run lint
npm run test
npm run build
npm run test:e2e
```

- 首先运行与变更相关的组件/流程测试，最终执行完整必要检查。
- 对导航状态、草稿保留、证据定位、异步响应与权限行为补充有意义测试。
- 单纯颜色、圆角和间距变化通过视觉验证，不编写镜像 CSS 实现的测试。
- 当前 Playwright 配置引用 `./venv/bin/python` 与 `./venv/bin/uvicorn`；执行前核对本地虚拟环境，避免把环境启动失败误判为功能失败。
- E2E seed 使用专用测试数据库，执行前确认目标路径，不能指向用户业务数据库。
- 现有 e2e 文件覆盖驾驶舱、选股器和异动；Market、Factor Lab 根据改动补齐关键路径。

### 10.4 可用性验收

- 在代表性桌面视口中，股票身份、价格日期和关键风险无需长距离滚动即可识别。
- 用户能从概览清楚找到估值假设、财务证据和价格图表入口。
- 所有原有能力都有可见入口，迁移过程中无孤立模块。
- 表格数值对齐、金额单位一致、缺失值明确，关键内容不以省略号永久隐藏。
- 风险提示、数据日期和覆盖率在浅深色下均可读。
- 键盘完成搜索、导航、切换分区和关闭弹窗，焦点可见。
- 手机可操作主要功能，无被遮挡的按钮和页面级意外横向溢出。

### 10.5 性能验收

- 使用相同浏览器、视口、数据与缓存条件对比改造前后结果。
- 首轮记录至少三次样本并比较中位数，排除后端同步等不可比因素。
- 关键加载与交互指标若恶化超过约 10%，先定位原因再决定是否接受；该值为项目内部回归阈值。
- 主题切换、面板展开、分区切换不会额外发起 AI 或 SEC 分析请求。
- 保留图表动态加载；避免所有不可见图表同时初始化。
- 不以卸载图表的方式丢失用户参数；状态与昂贵渲染生命周期合理分离。
- 不出现因字体、骨架高度或错误提示造成的明显布局跳动。

## 11. 风险与缓解措施

| 风险 | 缓解措施 |
| --- | --- |
| 页面重排导致能力入口遗漏 | 建立现有组件到新分区的映射，逐项验收 |
| 分区卸载丢失估值草稿 | 将工作状态保留在稳定父层，增加切换回归 |
| 证据跳转找不到隐藏图表 | 分区激活、指标设置、渲染完成后顺序定位 |
| 视觉简化隐藏数据限制 | 风险与缺失摘要持续可见，详情保留一跳可达 |
| 深色主题图表难读 | HTML 与两套图表库同时进行主题审查 |
| 固定侧栏挤压中等屏幕 | 按内容宽度收起侧栏，优先保障研究区 |
| 吸顶与内部滚动冲突 | 明确主滚动容器，验证缩放、手机键盘和锚点 |
| 全局 token 变更影响旧页面 | 基础迁移时同时检查所有页面，分批替换固定色值 |
| 改版引入重复请求 | 沿用现有取消与请求管理，记录切换时请求数 |
